## PROPOSAL PEROMBAKAN GEOMETRY PIPELINE

### 1. Masalah yang Diselesaikan
Saat ini alur data melakukan konversi yang tidak perlu:
$$\text{Array titik mm } [x, y] \xrightarrow{\text{dikali } \frac{96}{25.4}} \text{String SVG } (\text{mround, } d="M... L...") \xrightarrow{\text{Regex tokenize}} \text{Array } \xrightarrow{\text{dikali } \frac{25.4}{96}} \text{Array titik mm}$$

Kerugian saat ini:
- **CPU & Memori Terbuang:** String SVG puluhan ribu karakter diparsing ulang oleh Regex setiap kali ada parameter CAM diubah (feedrate, tabs, dogbone, dll).
- **Kehilangan Presisi:** Pembulatan string `mround(3)` lalu dikonversi balik menghasilkan *rounding jitter*.
- **Bug Variable Leak:** `isInside()` mengotori scope global `window` dengan variabel `inside`, `i`, `j`, `xi`, `yi`.

---

### 2. Rencana Arsitektur Baru: Direct Geometry Cache

Kita memperkenalkan model memori langsung: `parsedGeometryData`.

```text
                     [ pathstoText1(buff) ]
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
 [ parsedGeometryData ] (BARU)               [ text1 ] (LAMA)
  - Array of Shape Objects                    - Tetap diisi string SVG
    { points, closed, sty, ... }                untuk kompatibilitas
  - Presisi float murni (mm)                    downloadsvg & paste
  - Siap pakai langsung
            │
            ▼
    [ myFunction() ]
  - Jika ada parsedGeometryData:
    LANGSUNG iterasi titik (BYPASS regex & string parse!)
  - Jika dari file upload SVG luar (tidak ada parsedGeometryData):
    Fallback ke svgPathToCommands(text1)
```

---

### 3. Tahapan Implementasi

#### Tahap 1: Perbaikan Bug Global Scope di `isInside()`
- **Lokasi:** `frontend/public/karyacnc.js` (baris 2555)
- **Tindakan:** Deklarasikan variabel dengan `let`/`const` dan ubah loop array ke integer standar `for (let i = 0; ...)`.
- **Efek:** Mencegah loop ray-casting merusak variabel `i` atau `j` di fungsi lain.

#### Tahap 2: Simpan Geometri Bersih di `pathstoText1()`
- **Lokasi:** `frontend/public/appcore.js` (baris 4565–4625)
- **Tindakan:**
  Di loop `for (i in paths)`, selain merangkai string `t1`, kita simpan data murni ke struktur array `parsedGeometryData`:
  ```javascript
  // Disimpan langsung dalam satuan mm (sebelum dikali scale 96/25.4)
  parsedGeometryData.push({
      points: path.map(p => [p[0], p[1]]),
      closed: paths[i][8],
      flip: paths[i][1],
      sty: sty
  });
  ```
  Nilai `text1` tetap di-generate dan di-return seperti biasa agar fitur download SVG dan inspect tidak rusak.

#### Tahap 3: Modifikasi `myFunction()` untuk Membaca `parsedGeometryData`
- **Lokasi:** `frontend/public/appcore.js` (baris 3377 & 3468)
- **Tindakan:**
  - Jika `parsedGeometryData` tersedia dan panjangnya $> 0$:
    Iterasi langsung dari array `parsedGeometryData`. Tidak perlu memanggil `svgPathToCommands(text1)`.
  - Jika `parsedGeometryData` kosong (misalnya user melakukan drag-and-drop file `.svg` eksternal):
    Tetap panggil `svgdata = svgPathToCommands(text1)` sebagai jalur fallback.
  - Untuk setiap shape:
    Titik awal `X1, Y1` diumpankan ke `linepush(f1, X1, Y1, 1)`, sisa titik diumpankan ke `linepush(lastf, px, py)`, lalu ditutup dengan `gcodepush(lenmm, X1, Y1, lenmm, line, closed)`.

#### Tahap 4: Sinkronisasi saat Reset / File Baru
- Saat `WS_MESSAGE_RECEIVED` atau `loadhistory`: `parsedGeometryData` diperbarui.
- Saat user upload SVG eksternal: `parsedGeometryData = null`, sehingga sistem memakai parser SVG standar.

---

### 4. Hasil yang Akan Dicapai
1. **Kecepatan Parsing:** Vektor kompleks dari Inkscape diproses **3x hingga 5x lebih cepat**.
2. **Respon Parameter Instan:** Mengubah slider/input CAM di UI langsung mengolah titik tanpa harus melakukan regex tokenize ribuan baris teks SVG berulang kali.
3. **100% Backward-Compatible:** Format ekspor, download SVG, dan tampilan canvas tetap persis sama seperti sebelumnya.

`x = el.values[0] * scalex`.

### Jawaban Soal History: Perlu Diubah atau Tetap Teks?

Di history saat ini:
```javascript
text1_history.push([timestamp, buff, getSaveItSettings()]);
```
Yang disimpan di history adalah **`buff`** (string teks mentah format Inkscape `X:..\nP:..`), **BUKAN SVG `text1`**.

#### 1. Kenapa `buff` Lebih Baik Tetap Berupa Teks?
- **Kompak & Hemat Memori:** Format teks protokol Inkscape (`X:..\nP:..\n10,20\n`) sebenarnya jauh lebih ringkas daripada JSON objek JavaScript. JSON objek `[{points: [[10,20],...], style:...}]` memakan 3x–4x lebih banyak byte di `localStorage` karena pengulangan nama kunci (`"points"`, `"style"`, tanda kurung, koma).
- **Kompatibilitas:** Saat user klik tombol history, fungsi `loadHistoryIndex()` memanggil:
  ```javascript
  buff = text1_history[n][1];
  text1 = pathstoText1(buff); // Otomatis mengisi parsedGeometryData baru!
  refreshgcode();
  ```
  Karena kita sudah memasang `parsedGeometryData = []` di dalam `pathstoText1()`, **setiap kali history diklik, ia otomatis langsung memanfaatkan Direct Geometry Cache baru** tanpa menyentuh Regex SVG lagi!

#### 2. Tapi Ada 1 Masalah Nyata di History yang Perlu Diperbaiki:
Batas `localStorage` browser hanya 5MB–10MB:
- Jika `buff` mengandung gambar base64 besar (`I,...`), atau jika user membuka 10 file berturut-turut, `storage.setItem("history", ...)` akan melempar error `QuotaExceededError` (yang saat ini di-catch diam-diam).

### Bagaimana Pemisahan 2-Stage untuk Hitam & Merah Saja?

Sangat bersih dan terisolir:

#### **Stage 1 (Geometri Pisau & Urutan)**
Menghasilkan jalur fisik (koordinat X, Y):
- Dijalankan saat: file baru dimuat, `offset` diubah, `overcut2` (Dogbone) diubah, `tab` diubah, atau urutan sort diubah.
- Output: `sgcodes` sudah terisi seluruh koordinat garis hitam & merah yang sudah rapi terpotong dan terurut.

#### **Stage 2 (Pengaturan Kedalaman & Kecepatan Teks)**
Menghasilkan teks G-code (`lines2gcode`):
- Dijalankan seketika saat operator mengubah:
  - **Hitam:** `feed` (kecepatan potong), `zdown` / `deep`, `repeat`.
  - **Merah:** `pltfeed` (kecepatan merah), `carved` (kedalaman merah), `carvedp` / `firstd` (step pass merah).
  - **Bersama:** `pdn` (plunge), `pup` (safe Z), `trav` (rapid).
- **Di Stage 2 ini:** Clipper sama sekali tidak disentuh! Loop `lines2gcode` hanya membaca koordinat yang sudah jadi di `sgcodes` dan memasukkan nilai `F` dan `Z` baru.

Jika setuju, kita bisa mulai pasang mekanisme cache untuk `sgcodes` ini khusus untuk jalur cutting hitam & merah terlebih dahulu.
